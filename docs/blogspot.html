Membuat PPDB Online dengan Upload Pas Foto dan Bukti Pendaftaran Menggunakan PHP dan MySQL

Saya mengembangkan RuangDaftar, aplikasi simulasi Penerimaan Peserta Didik Baru atau PPDB dengan PHP dan MySQL. Selain menyimpan identitas calon siswa, aplikasi menyediakan unggah pas foto, pratinjau sebelum disimpan, pembaruan foto, dan bukti pendaftaran yang dapat dicetak.

Dalam aplikasi pendaftaran, informasi teks perlu dilengkapi foto agar profil calon siswa lebih mudah diperiksa. Saya menggunakan format pas foto tegak dengan rasio 3:4. Setelah data dan foto tersimpan, pengguna dapat membuka bukti pendaftaran lalu mencetaknya atau menyimpan sebagai PDF melalui dialog cetak browser.

Buka demo RuangDaftar · Lihat source code di GitHub

1. Menyusun Alur Pendaftaran

Alur dimulai dari formulir tambah siswa. Pengguna mengisi nama lengkap, sekolah asal, jenis kelamin, agama, dan alamat, lalu memilih pas foto. JavaScript menampilkan pratinjau, tetapi server tetap memeriksa seluruh isian dan file secara mandiri. Setelah penyimpanan berhasil, aplikasi mengarahkan pengguna ke halaman detail.

Halaman detail menampilkan identitas, foto, dan status kelengkapan. Bukti pendaftaran hanya tersedia untuk siswa yang sudah memiliki foto. Enam data awal merupakan data fiktif tanpa foto untuk mencoba proses melengkapi profil melalui halaman edit. Data awal tidak dibuat ulang setelah dihapus.

2. Menyiapkan Struktur Database

Database lokal bernama ppdb_sekolah dengan tabel calon_siswa. Kolom identitas disimpan bersama waktu pendaftaran dan penanda ruang demo. Saya menambahkan foto untuk byte gambar, foto_mime untuk tipe gambar, serta foto_nama untuk nama acak yang dibuat server.

CREATE TABLE calon_siswa (
    id INT NOT NULL AUTO_INCREMENT,
    workspace_id CHAR(32) NOT NULL,
    nama VARCHAR(64) NOT NULL,
    alamat VARCHAR(255) NOT NULL,
    jenis_kelamin VARCHAR(16) NOT NULL,
    agama VARCHAR(16) NOT NULL,
    sekolah_asal VARCHAR(64) NOT NULL,
    created_at DATETIME NOT NULL,
    foto MEDIUMBLOB NULL,
    foto_mime VARCHAR(16) NULL,
    foto_nama VARCHAR(40) NULL,
    PRIMARY KEY (id),
    INDEX siswa_workspace (workspace_id, id)
);

Saya memilih menyimpan byte foto di database supaya perubahan identitas dan gambar dapat dilakukan melalui satu perintah INSERT atau UPDATE. Untuk demo berukuran kecil, cara ini menjaga konsistensi data dan foto. Aplikasi membatasi maksimal 30 siswa dan total byte foto 8 MB per ruang demo. Setiap foto maksimal 1 MB.

3. Menyiapkan Folder dan Formulir Upload

Folder storage/images/ berada di luar document root. Folder dibuat otomatis dan dipakai untuk menampung unggahan sementara yang sudah lolos validasi. PHP memindahkan unggahan dengan move_uploaded_file(), membaca byte foto, lalu menghapus file sementara melalui blok finally. Nama file dari pengguna tidak digunakan sebagai path penyimpanan.

Formulir upload harus menggunakan metode POST dan enctype="multipart/form-data". Input file bernama foto akan dibaca PHP melalui $_FILES. Atribut accept membantu pemilihan gambar di browser, sedangkan keputusan penerimaan tetap ditentukan server.

<form method="post" action="/proses-pendaftaran.php"
      enctype="multipart/form-data">
    <!-- Isian identitas dan token CSRF -->
    <label for="foto">Unggah pas foto</label>
    <input type="file" id="foto" name="foto"
           accept="image/jpeg,image/png" required>
    <button type="submit">Simpan pendaftaran</button>
</form>

Pratinjau dibuat dengan URL.createObjectURL(). JavaScript memeriksa ukuran, tipe file, dan dimensi sebelum menampilkan gambar. Object URL sebelumnya dilepas ketika pengguna memilih foto lain. Pratinjau hanya berlaku di browser dan belum berarti file sudah tersimpan.

4. Memvalidasi Pas Foto di Server

Validasi memeriksa kode kesalahan upload, sumber file melalui is_uploaded_file(), ukuran sebenarnya dengan filesize(), MIME melalui Fileinfo, dan informasi gambar menggunakan getimagesize(). Pemeriksaan ini tidak bergantung pada ekstensi atau MIME yang dikirim browser. SVG, GIF, dan berkas teks yang diberi ekstensi gambar ditolak.

Dimensi yang diizinkan adalah 150 x 200 sampai 2400 x 3200 piksel. Rasio lebar terhadap tinggi mendekati 0,75 dengan toleransi 0,025. Foto persegi atau mendatar harus dipotong terlebih dahulu. Ukuran cetak 3 x 4 cm berbeda dari jumlah piksel; rasio 3:4 dipakai untuk menjaga proporsi pada layar dan bukti cetak.

$mime = (new finfo(FILEINFO_MIME_TYPE))->file($tmp);
$info = @getimagesize($tmp);

if (!isset($types[$mime]) || !$info || $info[2] !== $types[$mime][1]) {
    return [null, 'Isi file harus berupa gambar JPG atau PNG yang valid.'];
}

[$width, $height] = $info;
if (abs($width / $height - 0.75) > 0.025) {
    return [null, 'Gunakan foto tegak dengan rasio 3:4.'];
}

Setelah semua pemeriksaan lolos, server membuat nama acak menggunakan bin2hex(random_bytes(16)). Penyimpanan memakai prepared statements PDO dengan parameter foto bertipe PDO::PARAM_LOB. Jika ada kesalahan, formulir mempertahankan identitas dan menampilkan pesan di dekat kolom. Pengguna memilih ulang file karena browser tidak mengizinkan pengisian otomatis input file.

5. Menampilkan, Mengganti, dan Menghapus Foto

Foto ditampilkan melalui endpoint foto.php?id=.... Endpoint mengambil foto berdasarkan ID sekaligus workspace_id milik sesi aktif. Respons menggunakan MIME tersimpan, nama acak, header X-Content-Type-Options: nosniff, serta larangan cache bersama. Mengganti ID pada URL tidak memberikan akses ke foto dari ruang demo lain.

Pada halaman edit, input foto bersifat opsional jika foto sebelumnya sudah tersedia. Membiarkan input kosong mempertahankan foto lama. Mengunggah gambar baru yang valid mengganti foto pada baris yang sama. Jika pengganti ditolak, identitas dan foto lama tetap tersimpan. Menghapus pendaftaran juga menghapus byte foto yang berada pada baris tersebut.

Semua perubahan memerlukan POST dan token CSRF yang sesuai sesi. Tombol hapus membuka halaman konfirmasi terlebih dahulu. Nilai pengguna yang ditampilkan pada HTML melalui htmlspecialchars(), sementara nilai SQL dikirim sebagai parameter terpisah.

6. Membuat Bukti Pendaftaran

Halaman bukti.php menampilkan nomor pendaftaran, nama sekolah, tahun ajaran, waktu pendaftaran, identitas calon siswa, dan pas foto. Nomor dibuat dari ID data dan berlaku dalam ruang demo masing-masing. Aplikasi ini merupakan simulasi, sehingga bukti tidak menyatakan hasil seleksi atau penerimaan siswa nyata.

Tombol Cetak / Simpan PDF memanggil window.print(). CSS @media print menyembunyikan navigasi dan tombol, menggunakan halaman A4, serta memberi foto area 30 x 40 mm. Pengguna memilih printer atau opsi Save as PDF pada browser. Rendering cetak dan hasil PDF belum diverifikasi melalui browser otomatis di lingkungan pengerjaan.

7. Menjalankan Lokal dan Deployment

Untuk mencoba lokal, gunakan PHP 8.2 atau lebih baru dengan ekstensi PDO, pdo_sqlite, mbstring, Fileinfo, dan cURL. Jalankan php -S localhost:8000 -t public. Mode awal membuat database SQLite secara otomatis. Untuk MySQL atau MariaDB, impor database/mysql.sql ke database khusus lalu atur DB_DRIVER=mysql dan variabel koneksi pada file .env.

Demo Vercel menggunakan PHP dengan SQLite dan snapshot di Vercel Blob privat. Snapshot mencakup sesi, identitas, dan byte foto, sehingga data tidak hanya berada pada filesystem sementara serverless. Setiap request membaca snapshot terbaru. Penulisan bersyarat menggunakan ETag mencegah dua perubahan bersamaan menimpa data tanpa diketahui. Snapshot dan cookie memiliki masa berlaku tujuh hari.

Pemisahan ruang menggunakan cookie HttpOnly dan SameSite=Lax, serta Secure pada HTTPS. Ruang demo ini belum memakai akun petugas. Gunakan identitas dan gambar contoh. Konfigurasi rahasia, database lokal, dan unggahan tidak dimasukkan ke repository GitHub.

8. Pengujian dan Hasil Pembelajaran

Pengujian HTTP memeriksa unggah PNG, penggantian ke JPEG, foto lama saat edit tanpa unggahan, penolakan gambar tidak valid, dimensi, rasio, ukuran, token CSRF, escaping HTML, pembatasan akses antar sesi, bukti, pencarian, serta penghapusan data dan foto. Laporan hasil pengujian tersedia di repository dan catatan deployment menjelaskan batas verifikasi produksi.

Melalui proyek ini, saya mempelajari bahwa upload gambar memerlukan alur yang utuh: menerima formulir, memeriksa file, menyimpan secara konsisten, mengatur akses, menampilkan gambar, dan membersihkan datanya ketika pendaftaran dihapus. Bukti cetak melengkapi alur tersebut menjadi satu pengalaman pendaftaran yang lebih teratur.
